# Пауза ноги matrix-бота при ручном закрытии + ручное возобновление

**Дата:** 2026-07-09
**Статус:** дизайн согласован, ожидает ревью

## Проблема

Когда пользователь вручную закрывает позицию ноги matrix-бота (лонг или шорт),
стратегия завершает цикл, но лега остаётся `status='active'` без нового цикла —
зомби-состояние. Дальше возможны два нежелательных исхода:

- при живом движке зомби-watchdog остановит легу → `ensureMatrixStrategies`
  **тут же пересоздаст** её на следующем тике (бот сам заново откроет монету),
  что противоречит намерению пользователя «я закрыл — пусть стоит»;
- при мёртвом движке лега просто висит в неопределённом состоянии.

Пользователь считает, что ручное закрытие **должно** ставить ногу на паузу.
Нужно сделать это явным, предсказуемым состоянием и дать способ снова запустить
монету.

## Решение (кратко)

Ввести явный статус ноги `paused`. Ручное (внешнее) закрытие позиции ноги
переводит **только эту ногу** в `paused`; `ensureMatrixStrategies` её не
пересоздаёт; движок её не грузит. Возобновление — ручная кнопка на карточке ноги,
которая флипает `paused → active` и запускает свежий цикл.

Область — **по-ножно**: закрытие одной ноги не трогает вторую (для остановки
второй есть существующая кнопка на карточке).

## Поведение

### Статус `paused`

- Новое значение статуса стратегии `paused`. Колонка `strategies.status` — обычный
  `TEXT` без CHECK-констрейнта (см. `migrations/006_strategies.sql`,
  `migrations/040_matrix_sl.sql`), поэтому новое значение добавляется без миграции
  схемы.
- Семантика: «остановлена пользователем, НЕ пересоздавать автоматически» — в отличие
  от `stopped`, которую бот пересоздаёт.

### Триггер паузы (постановка в `paused`)

Условие: позиция ноги matrix-бота ушла в ноль **из-за внешнего действия**
(пользователь закрыл вручную из приложения или напрямую на бирже; ликвидация), а
не из-за собственной логики стратегии (TP / SL / paired-close / remnant/tail /
самозакрытие ghost-remnant).

Действие при срабатывании:
1. Отменить оставшиеся ордера ноги (DCA-лимитники, TP/SL).
2. Закрыть цикл (как сейчас — `result='manual_close'`).
3. Поставить **эту ногу** в `status='paused'` вместо обычного
   `maybeRestart → stopped` (который ведёт к пересозданию).
4. Вторую ногу не трогать.

### Пока лега в `paused`

- `ensureMatrixStrategies` пропускает это направление по монете (не пересоздаёт).
  Сейчас проверка существующей стратегии смотрит `status IN ('active','finishing')`
  — её нужно расширить так, чтобы наличие `paused`-ноги по (account, symbol,
  direction) тоже блокировало пересоздание.
- `checkMatrixZombieStrategies` не трогает `paused` (он работает только с `active`).
- Движок не грузит `paused` (`Engine.Start` и `Notify` берут только
  `active/finishing` + `stopped` с открытым циклом).

### Возобновление

- На карточке ноги в состоянии `paused` показывается кнопка «Возобновить».
- Нажатие → backend-endpoint: флип `paused → active`, запуск свежего цикла для
  этой ноги (позиция плоская, поэтому цикл начинается с нуля; если по какой-то
  причине на бирже есть позиция — переиспользуется существующий adopt-путь
  `ensureMatrixStrategies`).
- По-ножно: возобновляется только выбранная нога.

## Главный технический риск: надёжная детекция ручного закрытия

Label результата цикла **ненадёжен** как признак ручного закрытия:

- при живом движке внешнее закрытие идёт через `handlePositionCloseRetry` и
  помечается `result='manual_close'`;
- когда движок был offline в момент закрытия, оно детектируется на старте через
  `startup_reconcile` и помечается `result='ghost_close'`;
- `closeGhostPosition` метит `closedBySelf=true` и тоже пишет `ghost_close`, но это
  **самозакрытие бота** (закрытие remnant-позиции) — паузу ставить НЕ нужно.

Поэтому пауза должна опираться на **семантическое условие**, а не на строку
результата: «позиция ноги подтверждённо ушла в ноль (через `FetchPositions`) И это
не самозакрытие стратегии (`closedBySelf` не выставлен ни одним из путей
TP/SL/paired/remnant/ghost-remnant)».

Точки, которые кормят решение о паузе:
1. **Живое внешнее закрытие** — `handlePositionCloseRetry` (уже подтверждает
   позицию через `FetchPositions`, уже пишет `manual_close`). **Единственная точка
   паузы в v1.**
2. **Внешнее закрытие, пойманное на старте** — `startup_reconcile` (позиция ушла,
   пока движок был offline, → `ghost_close`). **В v1 паузу здесь НЕ ставим**:
   reconcile не может надёжно отличить «пользователь закрыл» от спурьёзной пропажи
   позиции (для которой уже есть обратный ремонт `reopenCycleIfPositionOpen`).
   Поведение offline-закрытий остаётся как сейчас (это осознанное ограничение v1,
   возможная доработка позже). При живом движке — основной сценарий — ручное
   закрытие всегда идёт через п.1 и корректно ставит паузу.

Прежде чем вешать паузу, нужно **проверить/дообеспечить**, что все собственные
закрытия бота метят себя (`closedBySelf=true`): TP, SL и matrix-TP уже метят;
**paired-close (`stopMatrixPair`) и полный SL всей позиции надо проверить явно** —
иначе их спутают с ручным закрытием и лега уйдёт в ложную паузу вместо нормального
цикла/пересоздания.

## Затрагиваемые компоненты

Backend:
- `pkg/strategy/cycle.go` — `handlePositionCloseRetry` / `maybeRestart`: ветка
  «внешнее закрытие ноги matrix-бота → paused».
- `pkg/strategy/startup_reconcile.go` — в v1 не трогаем (offline-закрытия остаются
  как есть; см. раздел о детекции).
- `services/api-gateway/matrix_engine.go` — `ensureMatrixStrategies` пропускает
  монету с `paused`-ногой; `checkMatrixZombieStrategies` (уже не трогает не-`active`).
- Проверка `closedBySelf` на путях paired-close / полного SL.
- Новый endpoint возобновления ноги (`paused → active` + старт цикла).

Frontend:
- Карточка ноги: индикация `paused` + кнопка «Возобновить».

## Крайние случаи

- **Закрыта одна нога, вторая жива:** первая `paused`, вторая продолжает торговать;
  пара «полупарная» до ручного возобновления — это ожидаемо.
- **Собственный paired-close бота:** обе ноги штатно останавливаются и
  пересоздаются (НЕ `paused`) — при условии корректной пометки `closedBySelf`.
- **Пользователь снова открыл позицию руками на `paused`-ноге:** при возобновлении
  adopt-путь поглотит существующую позицию (без дубля входа).
- **Возобновление при делистнутой/забаненной монете:** `ensureMatrixStrategies`-фильтры
  применяются как обычно.

## Вне области (YAGNI)

- Пауза/возобновление на уровне всего бота или всей монеты-пары одной кнопкой
  (выбран по-ножный вариант).
- Автоматическое возобновление по условию (только ручное).
- Пауза для не-matrix стратегий (grid/обычный хедж) — при желании отдельно.
