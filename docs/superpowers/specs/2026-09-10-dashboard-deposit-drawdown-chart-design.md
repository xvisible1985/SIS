# Три линии на графике дашборда: депозит, свободный депозит, просадка

## Проблема

Верхняя карточка дашборда (`HeroCard` в `frontend/src/pages/DashboardPage.tsx`) сейчас
показывает один график «Кривая P&L» — кумулятивный **реализованный** P&L по закрытым
сделкам за период (`cumSeries`, считается на фронте как running-sum `daily_pnl`). Это не
реальный баланс счёта: не учитывает нереализованный P&L, ввод/вывод средств, и не
показывает просадку явно (для просадки есть отдельная маленькая карточка ниже на
странице, в процентах).

Нужно заменить этот график на три линии в одной сетке:
1. **Депозит** — реальный equity счёта во времени, в $.
2. **Свободный депозит** — депозит минус текущая просадка от пика.
3. **Просадка** — на сколько $ текущий депозит ниже своего максимума за период.

## Источник данных: уже существующая таблица `balance_snapshots`

Новых механизмов сбора данных не требуется. Таблица `balance_snapshots`
(`migrations/023_balance_snapshots.sql`: `account_id, equity, created_at`) уже пишется
на каждый вызов `GET /accounts/:id/balance` (`services/api-gateway/accounts_handler.go`).
Проверено на локальной БД — для активно используемых аккаунтов накоплены сотни точек за
недели (например, один снапшот раз в 1–3 часа), этого достаточно для графика за
1д/7д/30д/90д/1г.

Ограничение: `balance_snapshots` пишется только когда фронт запрашивает баланс
**конкретного** аккаунта — как и сейчас работает виджет `Equity` в `HeroCard`
(`equity != null` только при выбранном конкретном аккаунте, не в режиме «все аккаунты»).
Новые три линии наследуют это же ограничение — это не новое поведение, а естественное
продолжение того, что уже так работает.

## Бэкенд: `services/api-gateway/dashboard_handler.go`

Новый блок в `GetDashboard`, использующий уже вычисленные `since`/`trunc`/`granularity`
(те же, что строят `daily_pnl`), — только когда `accountID != ""`:

```sql
SELECT bucket, equity FROM (
  SELECT DATE_TRUNC('<trunc>', created_at) AS bucket, equity,
         ROW_NUMBER() OVER (
           PARTITION BY DATE_TRUNC('<trunc>', created_at)
           ORDER BY created_at DESC
         ) AS rn
  FROM balance_snapshots
  WHERE account_id = $1 AND created_at >= $2
) s WHERE rn = 1
ORDER BY bucket ASC
```

Берём последний снапшот в каждом bucket'е (день/час — то же дробление, что у
`daily_pnl`) — это equity «на конец периода-бакета».

Новое поле в `dashboardResponse`:

```go
type dashboardEquityPoint struct {
	Day    string  `json:"day"`
	Equity float64 `json:"equity"`
}
```
`EquitySeries []dashboardEquityPoint json:"equity_series"` — тот же формат `day`
(`bucket.Format(time.RFC3339)`), что и у `daily_pnl`, но **не обязан** покрывать те же
самые бакеты 1-в-1 (в бакете могли быть сделки без баланс-снапшота или наоборот) —
фронт должен мёржить два ряда по ключу `day`, а не по индексу массива.

Пустой массив, если `accountID == ""` или снапшотов нет за период — фронт обязан
корректно обработать этот случай (см. ниже).

## Фронтенд: расчёт трёх линий

В новом компоненте графика (заменяет текущий вызов `<AreaChart>` в центральной колонке
`HeroCard`):

- Мёржим `equity_series` с бакетами `daily_pnl` по ключу `day` (используя ось X от
  `daily_pnl`, т.к. она уже задаёт диапазон периода) → массив `Deposit(t)` ($).
- `Peak(t)` = running max `Deposit` от начала периода до `t`.
- `Drawdown(t)` = `Peak(t) − Deposit(t)` (≥0, $).
- `FreeDeposit(t)` = `Deposit(t) − Drawdown(t)`.

Пример (подтверждён с пользователем): пик $10 → просадка до $6 → просадка сейчас $4 →
свободный депозит = $6 − $4 = **$2**.

**Fallback:** если `equity_series` пуст (нет снапшотов / выбраны «все аккаунты») —
показываем старый однолинейный график кумулятивного P&L (`cumSeries`), как сейчас,
вместо пустого места. Новое поведение — чистое дополнение, не регресс для тех сценариев,
где `equity_series` недоступен.

## Оси и вёрстка графика

- Ось Y (для «Депозит» и «Свободный депозит», общая шкала) — **абсолютные** значения $
  (не изменение от нуля периода).
- Ось X — 5 отметок дат (тот же паттерн, что уже в `PnLCurveCard`: индексы
  `0/25%/50%/75%/100%` через `periodShortLabel`), не только первая/последняя точка.
- «Просадка» рисуется **отдельной полосой внизу того же графика**, со своим
  (не подписанным числами) вертикальным масштабом — её амплитуда на порядок меньше
  депозита, в общей шкале с депозитом она была бы не видна.
- Легенда — 3 цветных маркера с подписями над графиком (Депозит / Свободный депозит /
  Просадка).

Цвета линий (согласовано визуально): Депозит — `T.blue` (`#5b8cff`), Свободный
депозит — `T.green` (`#5be0a0`), Просадка — `T.red` (`#fca5a5`).

## Перестройка `HeroCard` (десктоп)

- Пропорция колонок `grid-template-columns`: `minmax(0,1fr) minmax(0,2fr) minmax(0,1fr)`
  → `minmax(0,0.8fr) minmax(0,2.6fr) minmax(0,0.8fr)` (левая/правая уже, центр шире).
- Высота карточки увеличивается на ~30% (в первую очередь за счёт роста высоты самого
  графика: текущие 170px → ~220px, плюс место под легенду и подписи осей).
- `RecentTradesCard` справа от `HeroCard`+`DailyStatsStrip` в той же строке уже
  растягивается на высоту соседней колонки (`alignItems:'stretch'` в родительском
  grid, `flex:1; overflowY:'auto'` внутри карточки) — при увеличении высоты `HeroCard`
  она вырастет автоматически, без отдельных правок. Проверяется визуально при
  тестировании, но отдельного кода под это не требуется.
- Мобильная раскладка (`isMobile` в `HeroCard`) — **не трогаем** в этой задаче, остаётся
  с текущим однолинейным графиком.
- Отдельная карточка просадки в % (`DrawdownCard`, ниже на странице) — **не трогаем**.
- Большая отдельная карточка `PnLCurveCard` — **не трогаем**.
