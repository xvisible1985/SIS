# Объединение одиночных стратегий в пару привязкой к боту (drag-and-drop)

**Дата:** 2026-07-13
**Статус:** дизайн согласован, ожидает ревью

## Проблема

Есть detach (открепить стратегию от бота, `bot_id=NULL`), но **обратной операции нет**:
осиротевшую одиночную стратегию нельзя вернуть под управление бота через UI. В
результате две одиночные леги (например, long+short одного символа) не объединяются в
парную карточку и не получают парного закрытия — потому что и группировка в
`HedgePairCard`, и paired-close завязаны на `bot_id`.

## Решение (кратко)

Дать пользователю **перетащить одну одиночную карточку на противоположную** и, отпустив,
объединить их в пару через окно **«Привязать к боту»**: пользователь выбирает hedge- или
matrix-бота, обе леги получают конфиг этого бота и `bot_id`, после чего существующая
логика группировки сама собирает их в `HedgePairCard`, а движок бота берёт пару в
управление (paired-close, пересоздание, «Накоплено»).

## Поведение

### Взаимодействие (drag-and-drop)

- **Перетаскиваемые:** одиночные карточки стратегий (standalone `StrategyCard`).
- **Валидная цель дропа:** другая одиночная карточка с `тем же symbol` + `тем же
  account_id` + **противоположным** `direction`. Только такие цели подсвечиваются при
  наведении перетаскиваемой карточки; на невалидные бросить нельзя.
- **Дроп** валидной пары → открывается окно «Привязать к боту».
- Реализация DnD — деталь плана (HTML5 drag events либо лёгкая DnD-библиотека).

### Окно «Привязать к боту»

- Список **ботов пользователя на этом аккаунте** типа `hedge` или `matrix`
  (`strategy_config->>'bot_kind' IN ('hedge','matrix')`, `account_id` совпадает).
- **Origin-бот подсвечен**, если он известен (см. `origin_bot_id` ниже). Если у обеих
  лег origin неизвестен — подсветки нет.
- Если у любой из двух лег есть **открытая позиция на бирже** — показать
  **предупреждение** (вариант C: не блокируем, но честно предупреждаем, что конфиг бота
  накатится на живую позицию и сетка/TP/SL перевыставятся под бота).
- Выбор бота + подтверждение → `POST` bind-эндпоинт.

### Роли в паре

- **Matrix-бот:** роли по направлению — `long` = main, `short` = hedge (конвенция как в
  `ensureMatrixStrategies`/`checkMatrixPairedClose`).
- **Hedge-бот:** роли по **размеру позиции** — большая по notional (`size × mark`) =
  main, меньшая = hedge; на hedge-легу ставится `hedged_strategy_id = main.id`.
  Детерминированный фолбэк, если размеры равны или обе позиции плоские: main = лега с
  направлением `long`, hedge = `short`. (Bind плоских лег — редкий крайний случай.)

### Бэкенд: bind-эндпоинт

`POST /strategies/bind` — тело: `{ "strategy_a_id", "strategy_b_id", "bot_id" }`.

Шаги:
1. **Валидация** (иначе 4xx с понятным сообщением):
   - обе стратегии принадлежат пользователю;
   - у обеих `symbol` и `account_id` совпадают, `direction` противоположны;
   - `bot_id` принадлежит пользователю, на том же `account_id`, тип `hedge`|`matrix`;
   - у выбранного бота **нет уже существующей активной пары по этому символу**
     (иначе привязка создаст дубль — блок).
2. **Накатить конфиг бота** на ОБЕ строки: распарсить `bots.strategy_config` в
   `botCfgJSON`, вычислить конфиг-значения и `UPDATE` конфиг-колонки обеих стратегий —
   **переиспользуя логику реюза строки** (та же перезапись конфиг-колонок, что в
   reuse-ветке `createBotStrategy`; вынести в общий хелпер `applyBotConfigToStrategy`).
   `strategy_type` берётся от бота.
3. **Проставить связи:** `bot_id` на обе; для hedge-бота — определить main/hedge по
   размеру позиции (шаг «Роли») и записать `hedged_strategy_id` на hedge-легу.
4. **`Notify` движку** по обеим стратегиям → бот поглощает существующие позиции
   (adopt-путь уже есть) и берёт пару в управление.

### Персистентный origin-бот

- Новый столбец `strategies.origin_bot_id UUID` (nullable).
- Ставится **при создании** стратегии ботом (`createBotStrategy` пишет `origin_bot_id =
  bot_id`) и **НЕ обнуляется при detach** (в отличие от `bot_id`).
- Используется окном привязки для подсветки «какой бот породил эти стратегии».
- Ограничение: для стратегий, созданных/откреплённых ДО добавления столбца, origin
  неизвестен — подсветки для них не будет. Это принято.

### Конфиг на живой позиции (вариант C)

- Бэкенд **не блокирует** bind при открытой позиции.
- Фронт **предупреждает** в окне, что конфиг бота применится к живой позиции (сетка/TP/SL
  перевыставятся). Далее — обычный adopt-путь бота.

### Группировка (без новой логики)

Отдельная логика группировки не нужна: как только bind проставил `bot_id`
(и `hedged_strategy_id` для hedge), существующие Методы 1/2/3 в `TerminalPage`
(`renderItems`) сами соберут леги в `HedgePairCard`.

## Затрагиваемые компоненты

Backend:
- Миграция: `strategies.origin_bot_id`.
- `createBotStrategy` (`bot_engine.go`): писать `origin_bot_id`; вынести перезапись
  конфиг-колонок в общий хелпер `applyBotConfigToStrategy`, используемый и reuse-веткой,
  и bind-эндпоинтом.
- Новый bind-эндпоинт + роут (`strategy_handler.go` / `main.go`).

Frontend:
- DnD на одиночных карточках (`StrategyCard` / список в `TerminalPage`): drag source +
  валидные drop-цели с подсветкой.
- Окно «Привязать к боту»: список ботов аккаунта, подсветка origin, предупреждение об
  открытой позиции, вызов bind-API.
- API-клиент: функция bind.

## Крайние случаи

- **Обе позиции плоские при hedge-bind:** роль по фолбэку (direction / entry×size), не
  падаем.
- **У бота уже есть пара по символу:** блок с сообщением (не создаём дубль).
- **Разные символы / одинаковое направление / разные аккаунты:** дроп невалиден, окно не
  открывается.
- **Одна из лег уже привязана к боту (не одиночная):** не является drag/drop-целью
  (тянем/бросаем только standalone-карточки).
- **Origin неизвестен:** окно работает, просто без подсветки источника.
- **Открытая позиция:** предупреждение, но bind разрешён (вариант C).

## Вне области (YAGNI)

- Перетаскивание уже-парных карточек / переразбиение пар.
- Автоопределение «лучшего» бота — пользователь выбирает сам (origin лишь подсвечен).
- Кнопочный фолбэк вместо DnD — опционально, решить в плане (можно добавить для
  доступности/мобилы, но не обязателен для v1).
- Ретро-заполнение `origin_bot_id` для старых строк (данные утеряны).
